---
name: engineering-writing-style
description: >-
  在工程项目中生成任何供人阅读的文字时使用，包括临时回复、进度说明、TODO、任务标题、
  工作日志、技术解释、必要代码注释、需求和说明文档、审查意见、PR/提交说明以及最终汇报。
  默认面向不了解实现细节的普通项目同事，以项目事实写成自包含说明；禁止沿用会话或旧材料
  中的隐喻化工作简称、自造标签和抽象套话，必须改写为主体、条件、动作和结果。原样转录
  日志、机器格式或精确引文时不改写主体；不替代开发、调试、审查、Git 或知识沉淀 Skill，
  不主动发起代码或 API 重命名，只作为所有可见输出的表达约束叠加。
---

# 工程写作风格发现适配器

这是 Devin CLI 的项目级发现入口，不是第二份行为契约。唯一下一动作是读取 [唯一 Skill 事实源](../../../skills/engineering-writing-style/SKILL.md)；在该 Skill 完成场景判断前，不执行任务，也不读取任何 SPEC。适配器目录没有 `SPEC.md`；路由后遇到根 Skill 的 `./SPEC.md`，必须相对根 Skill 所在目录解析。
