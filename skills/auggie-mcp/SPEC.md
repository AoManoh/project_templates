# Auggie MCP Skill 规范

**版本**: 1.0.0
**适用范围**: 源码语义检索、影响面分析、调用链定位、任务进度索引恢复

---

## 1. 目标

本规范用于约束 AI Agent 使用 Auggie/Augment MCP 类能力时的事实边界和降级路径。

为什么：语义检索和任务索引可以显著提高恢复与定位效率，但它们不是当前事实本身。没有确认规则时，AI 容易把索引结果、缓存摘要或过期任务状态误当成源码、配置和用户确认。

---

## 2. 能力定义

| 能力 | 定义 | 可用于 | 不可用于 |
|------|------|--------|----------|
| 源码语义检索 | 基于自然语言从代码库中检索相关文件、符号、调用链和实现片段 | 找入口、找影响面、找根因线索 | 单独裁决当前实现、直接替代文件读取 |
| 外部任务索引 | 外部工具记录的任务拆分、进度、状态和候选下一步 | 上下文恢复、任务续接、进度提示 | 裁决需求、接口、配置、架构、完成状态 |

---

## 3. 事实源优先级

当 Auggie MCP 输出与其他来源冲突时，按以下顺序判定：

1. 用户最新明确确认。
2. 当前真实源码、配置、测试、运行结果和验证输出。
3. 当前阶段文档：`docs/requirements/`、`docs/development/`、`docs/refactor/`。
4. `AGENTS.md` 与相关 `skills/*/SKILL.md` / `SPEC.md`。
5. 外部任务索引、历史工作日志、参考资料和旧对话上下文。

外部任务索引位于最低事实层级，只能帮助定位下一步，不能覆盖上层来源。

---

## 4. 源码语义检索规范

### 4.1 进入条件

满足任一条件时优先使用语义检索：

- 不知道相关代码、配置、脚本或测试在哪个文件。
- 需要跨模块理解调用链、数据流或影响面。
- 需要为 review、debug、refactor 建立候选证据范围。
- 需要验证历史文档或对话中的说法是否仍符合当前源码。

### 4.2 检索要求

每次检索必须包含：

| 字段 | 要求 |
|------|------|
| 项目根 | 当前 `AGENTS.md` 所在目录或用户明确指定的仓库根 |
| 查询目标 | 说明要找的行为、接口、模块、错误、配置或风险 |
| 期望输出 | 期望得到文件路径、符号、调用链、风险点或验证线索 |

### 4.3 验证要求

语义检索返回后，必须执行：

1. 打开真实文件确认内容。
2. 核对上下文是否与当前任务匹配。
3. 必要时用精确文本搜索补全遗漏。
4. 只在真实文件确认后引用路径、行号或实现事实。

---

## 5. 外部任务索引规范

外部任务索引只允许回答：

- 当前可能做到哪一步。
- 哪些任务可能已完成、待做或被阻塞。
- 上下文恢复时下一步候选项是什么。

外部任务索引不得回答：

- 某接口现在应该如何设计。
- 某配置当前值是什么。
- 某实现是否已经完成。
- 某架构决策是否仍然有效。
- 某验证是否已经通过。

这些问题必须回到源码、配置、验证输出、阶段文档或用户最新确认。

---

## 6. 降级与冲突处理

| 场景 | 处理 |
|------|------|
| MCP 工具不可用 | 使用文件列表、精确搜索、真实文件读取和现有测试输出恢复 |
| 检索结果为空 | 改写查询，加入模块名、错误文本、接口名、文件类型或相邻概念 |
| 检索结果与真实文件冲突 | 以真实文件为准，并记录检索结果疑似过期 |
| 任务索引与阶段文档冲突 | 以当前阶段文档和用户最新确认为准 |
| 多个事实源互相冲突 | 暂停下结论，列出冲突并请求确认当前权威来源 |

---

## 7. 禁止事项

| 禁止事项 | 为什么 |
|----------|--------|
| 只看 MCP 摘要就修改代码 | 摘要可能缺上下文或过期 |
| 用任务索引证明任务已完成 | 完成状态必须由源码、验证和当前阶段文档证明 |
| 用语义检索替代精确匹配 | 标识符、错误文本、配置键等需要全量匹配时必须使用精确搜索 |
| 在多个文档重复维护同一 MCP 细则 | 容易形成新旧规则并存，违反单一事实源 |
