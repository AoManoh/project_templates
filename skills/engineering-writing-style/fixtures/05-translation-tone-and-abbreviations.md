# 夹具 05：翻译腔动词、缩减词、生造词、引号强调与对比句式

来源：linux.do 帖子《分享一个30行去除AI味的提示词》（https://linux.do/t/topic/2850228 ，作者 qwe2，2026-09-03）中的错误示范与修改后示范。五组句子均为帖子原文，只去掉了加粗标记。帖子的六条规则里有五条并入 SPEC §2.7；"禁止使用中文弯引号 U+201C/U+201D"一条未采纳，理由见 SPEC §2.7。

任务：把每组"输入"交给只加载本 Skill 的新会话改写，逐条对照判定要点。

## 1. 翻译腔动词

输入：当遇到大流量时，如果缓存被击穿，系统能否扛住压力？如果代码有漏洞，很容易被黑客打穿防线。

帖子给出的改写：当遭遇大流量并发时，若缓存失效导致请求直达数据库，系统能否承受此负载压力？若代码存在安全漏洞，防线极易被黑客攻破。

判定要点：击穿、扛住、打穿不再出现；"缓存被击穿"写成实际现象（缓存失效后请求直达数据库）；"扛住压力"写成可观察的判断（在该负载下是否仍按预期响应）。

## 2. 缩减词

输入：服务器出现高负，导致微服响应超时，建议排查连池配置。

帖子给出的改写：服务器出现高负载情况，导致微服务响应超时，建议排查数据库连接池配置。

判定要点：高负、微服、连池全部写回全称；不新增其他缩略。

## 3. 引号包裹的行话与短句

输入：这套系统做到了"高可用"，前端实现了"多端适配"，后端进行了"冷热分离"，线程池本身只提供"常驻线程反复取活"的机制。

帖子给出的改写：这套系统具备高可用性，前端实现了多平台适配，后端实现了冷热数据分离存储，线程池本身只提供常驻线程循环取任务的机制。

判定要点：四处引号全部去掉，每个被引号包裹的词都写成实际含义；输出中的引号只出现在逐字引用或字符串上。

## 4. 生造复合词

输入：该架构具有极高的高并发抗性，代码的自解释度出色，并展现出良好的容灾力。

帖子给出的改写：该架构能够有效应对高并发冲击，代码可读性强且易于理解，同时具备良好的容灾能力。

判定要点：高并发抗性、自解释度、容灾力不再出现；改写用常规词或写出能力的实际表现（例如在多少并发下响应仍在预算内、函数名说明用途、节点故障后多久恢复）。"有效应对高并发冲击"仍是空评价，若输出给出具体表现则优于帖子改写。

## 5. "不是……而是……"句式

输入：该接口响应变慢的原因不是服务器负载过高，而是缓存策略失效。

帖子给出的改写：该接口响应变慢的原因是缓存策略失效。

判定要点：没有纠错或对比对象时直接陈述肯定结论；如果上下文确有被否定的错误判断需要纠正，可以保留对比，但要写出被否定判断的来源。

## 对照句（不应被误改）

输入：`RetryPolicy.Do` 在 `ClassTransient` 与 `ClassRateLimit` 两类错误上重试，最多 `MaxRetries+1` 次尝试。

判定要点：标识符与数字原样保留；该句不含上述任何模式，改写后语义不变。
