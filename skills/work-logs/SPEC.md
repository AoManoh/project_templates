# 工作日志规范

**版本**: 1.1.0
**创建日期**: 2026-03-10
**适用范围**: `work-logs` Skill 生成的任务日志与今日日志总结

---

## 1. 目标

本规范定义工作日志的字段、模板、标签、状态、文档结构与自检标准。

为什么：工作日志如果只有“记一下”而没有统一结构，后续维护者很难快速恢复上下文；但如果把所有模板细则都堆在 `SKILL.md`，入口文档又会失去职责边界。

### 1.1 维护边界

本文件是 `work-logs` 模板、字段、标签、状态、结构与自检要求的唯一维护位置；`SKILL.md` 只保留触发条件、执行流程和快速参考。

---

## 2. 文件命名与时间规则

### 2.1 文件命名

```
docs/work-logs/YYYY-MM-DD.md
```

### 2.2 时间约束

1. 创建或追加日志前，必须先获取真实的中国上海时间。
2. 以真实日期决定写入哪个 `YYYY-MM-DD.md` 文件。
3. 同一天的多个任务必须写入同一份日志文件。

---

## 3. 最小必填字段

每条任务日志至少回答以下三个问题：

| 问题 | 说明 | 示例 |
|------|------|------|
| **做了什么** | 一段话描述完成的工作 | “将 MCP 工具改为延迟初始化模式” |
| **为什么做** | 任务来源或问题背景 | “MCP 服务不可用时导致启动失败” |
| **改了什么** | 修改的文件列表 | “修改 11 个文件” |

### 3.1 按需补充项

| 任务性质 | 建议补充 | 目的 |
|----------|----------|------|
| 问题排查类 | 怎么定位的问题 | 传授排查思路 |
| 方案选择类 | 考虑过哪些方案、为什么选这个 | 记录决策过程 |
| 有学习价值 | 学到了什么（技术知识点、设计原则） | 知识沉淀 |
| 跨日期任务 | 关联文档链接 | 任务追溯 |
| 简单修改 | 无需补充，三要素足够 | 避免形式主义 |

## 4. 任务日志模板

### 4.1 基础模板

```markdown
# 任务标题 [标签]

**日期**：YYYY年MM月DD日 HH:MM:SS
**状态**：已完成 / 进行中 / 暂停

## 做了什么

一句话或简短描述完成的工作。

## 为什么做

任务来源、问题背景、或需求描述。

## 改了什么

- `path/to/file1.py` - 修改说明
- `path/to/file2.py` - 修改说明
```

### 4.2 复杂任务模板

```markdown
# 任务标题 [标签]

**日期**：YYYY年MM月DD日 HH:MM:SS
**状态**：已完成
**工作量**：修改 X 个文件
**关联任务**：[前序任务名称](./YYYY-MM-DD.md#锚点)

## 做了什么

完成的工作描述。

## 为什么做

任务来源、问题背景。

## 问题定位过程（问题排查类补充）

### 第一步：做了什么
**为什么这么做**：解释思路
**发现了什么**：结果

### 第二步：...

## 方案选择（方案选择类补充）

| 方案 | 优点 | 缺点 | 是否采用 |
|------|------|------|----------|
| 方案A | ... | ... | 否 |
| 方案B | ... | ... | 是 |

**为什么选择方案B**：理由说明

## 改了什么

| 文件 | 修改内容 |
|------|----------|
| `path/to/file.py` | 修改说明 |

## 学到了什么（有学习价值时补充）

### 技术知识点
- 知识点1
- 知识点2

### 设计原则
- 原则1
- 原则2

## 遗留问题

- 问题1（优先级：高/中/低）
- 无
```

## 5. 今日日志总结模板

### 5.1 位置与时机

- **位置约束**：永远放在日志文档的最后。
- **更新时机**：每完成一个任务后，同步更新。

### 5.2 总结模板

```markdown
# 今日日志总结

**日期**：YYYY年MM月DD日
**标签**：[总结]

## 完成任务清单

| 序号 | 任务 | 类型 | 状态 |
|------|------|------|------|
| 1 | 任务名称 | Bug修复 | 完成 |

## 修改文件汇总

| 文件路径 | 修改类型 | 说明 |
|----------|----------|------|
| `path/to/file.py` | 修改 | 修改说明 |

## 遗留问题

- 无

## 经验教训（可选）

1. 经验1
```

## 6. 标签与状态

### 6.1 标签分类

| 标签 | 说明 |
|------|------|
| `[Bug修复]` | 修复代码缺陷 |
| `[功能开发]` | 新功能实现 |
| `[环境配置]` | 环境搭建和配置 |
| `[重构]` | 代码重构 |
| `[优化]` | 性能或代码优化 |
| `[文档]` | 文档编写和更新 |
| `[学习]` | 学习和探索 |
| `[总结]` | 会话/阶段总结 |

### 6.2 状态标记

| 状态 | 含义 | 使用场景 |
|------|------|----------|
| 已完成 | 任务已完成并验证 | 默认状态 |
| 进行中 | 任务正在进行 | 跨会话任务 |
| 暂停 | 任务暂停，待后续继续 | 被阻塞或优先级调整 |
| 已取消 | 任务取消，不再执行 | 需求变更 |

---

## 7. 日志文档结构

每日工作日志文档的结构如下：

```
YYYY-MM-DD.md
├── 任务日志 1（按 timeline 顺序）
├── 任务日志 2
├── ...
├── 任务日志 N
└── 今日日志总结（永远放在最后）
```

**编排规则**：

- 任务日志按完成时间的 timeline 顺序排列。
- `今日日志总结` 永远放在文档最后。

---

## 8. 自检与验收

写完日志后，AI 助手必须自问：

| 自检问题 | 不通过时的处理 |
|----------|----------------|
| 三个月后看这条日志，能快速理解当时做了什么吗？ | 补充背景和细节 |
| 遇到类似问题时，这条日志能帮我快速解决吗？ | 补充定位过程和解决方案 |
| 初级程序员看这条日志，能学到东西吗？（仅复杂任务） | 补充“为什么”和“学到了什么” |

日志完成时，至少满足以下条件：

1. 已使用真实时间写入正确日期文件。
2. 任务日志已回答最小必填字段。
3. `今日日志总结` 已更新且仍位于文档最后。
4. 对复杂任务，已补充必要的定位、方案或经验信息。
