# DeepWiki 文档生成 Skill

**skill_id**: `deepwiki`
**版本**: 1.2.1
**output_dir**: `docs/deepwiki/`

---

## 1. 概述

本技能定义 AI Agent 自动化生成 DeepWiki 文档的标准流程，使 AI Agent 能够为任何软件项目生成结构化的技术文档。

### 1.1 触发条件

| 触发方式 | 条件 |
|----------|------|
| 显式触发 | 用户指令包含关键词：`deepwiki`、`wiki文档`、`项目文档`、`技术文档` |

### 1.2 前置依赖

| 依赖 | 用途 | 必要性 |
|------|------|--------|
| Augment Codebase | 源码检索、项目分析 | 必需 |
| view 工具 | 读取源码文件确认 | 必需 |

### 1.3 语言与格式要求

所有生成产物必须统一遵守 [SPEC.md](./SPEC.md) 中的语言与格式规范。

为什么：`SKILL.md` 负责定义触发条件、执行入口和流程骨架；语言、图表、页面元素与格式细则应由 `SPEC.md` 统一维护，避免同一规则在两个文件中并存导致事实源漂移。

### 1.4 关联规范

报告格式标准详见：[SPEC.md](./SPEC.md)

## 4. 流程阶段定义

### 4.1 阶段一：分析项目类型与组织模式

**目的**: 分析项目类型，确定文档组织模式

**应收集的信息**:
- `repo_path`: 项目根目录路径
- `readme_content`: README 文件内容（可选）

**阶段产物**:
- 项目类型判断
- 推荐的组织模式
- 核心模块列表
- 项目类型特定章节建议
- 置信度说明

**判断逻辑**:
```
1. 检查主要编程语言
   - C/C++/Rust -> 可能是基础设施/编译器
   - Python -> 可能是 AI/ML 框架
   - Go -> 可能是云原生/分布式系统
   - TypeScript + Go/Python -> 可能是全栈应用

2. 检查核心抽象
   - 有 Pipeline/Workflow -> 组件-管道导向
   - 有 Model/Inference -> AI/ML 框架
   - 有 Cluster/Node -> 分布式系统
   - 有 Frontend/Backend -> 全栈应用
   - 有 MLIR/IR/Dialect -> 编译器基础设施

3. 检查目录结构
   - packages/ + pkg/ -> 全栈 Monorepo
   - cmd/ + pkg/ -> Go 项目
   - src/ + tests/ -> 标准项目

4. 匹配项目类型模式
5. 选择最佳组织模式
6. 确定项目类型特定章节
```

---

### 4.2 阶段二：生成文档目录结构

**目的**: 生成文档目录结构

**依赖前序阶段**:
- 阶段一输出的项目类型判断与组织模式
- `depth`: 目录深度（默认 2）

**阶段产物**:
- 主章节与子章节目录结构
- 总章节数与总小节数估计

**生成规则**:
1. 必须包含 Overview 和 System Architecture
2. 根据组织模式选择章节模板
3. 根据核心模块动态生成领域章节
4. 根据项目类型添加特定章节
5. 章节数量控制在 6-12 个（推荐 9 个）

---

### 4.3 阶段三：按章节提取相关源文件

**目的**: 为每个章节提取相关源文件

**应收集的信息**:
- `chapter_id`: 章节 ID
- `chapter_title`: 章节标题
- `repo_path`: 项目根目录

**阶段产物**:
- 当前章节与相关源文件映射
- 文件数量统计

**提取规则**:
1. 根据章节主题匹配文件名和目录名
2. 分析文件内容和导入关系
3. 优先选择核心实现文件
4. 必要时补充配置、脚本、测试和文档文件，避免只引用主代码文件
5. 限制文件数量（5-15 个）

---

### 4.4 阶段四：按需生成 Mermaid 图表

**目的**: 为章节生成 Mermaid 图表

**应收集的信息**:
- `chapter_type`: 章节类型（architecture|flow|sequence|class）
- `source_files`: 相关源文件列表
- `context`: 章节上下文

**阶段产物**:
- 图表类型
- Mermaid 图表代码
- 图表说明文字

**图表类型选择**:
| 章节类型 | 推荐图表 |
|----------|----------|
| 架构概述 | graph TB/LR |
| 数据流 | graph LR |
| API 交互 | sequenceDiagram |
| 类关系 | classDiagram |
| 状态转换 | stateDiagram-v2 |

**语言要求**：图表文字的权威细则以 [SPEC.md](./SPEC.md) 为准。

---

### 4.5 阶段五：生成章节正文内容

**目的**: 生成章节正文内容

**应收集的信息**:
- `chapter_id`: 章节 ID
- `chapter_title`: 章节标题
- `source_files`: 相关源文件
- `mermaid_diagram`: 图表（可选）

**阶段产物**:
- 章节标题
- 相关源文件列表
- 目的与范围
- 正文技术说明
- 必要的图表、表格与源码引用

**内容要求**:
1. 必须包含"相关源文件"列表
2. 必须包含"目的与范围"章节
3. 技术说明要具体，避免空泛
4. 适当引用源码 `[file.py:line-range]()`
5. 语言、图表、格式与页面元素要求统一遵守 [SPEC.md](./SPEC.md)

## 5. Skill 编排流程

### 5.1 完整生成流程

```
1. 分析项目类型与组织模式
   |
2. 生成目录结构
   |
3. 遍历每个章节：
   |-- 提取相关源文件
   |-- 按需生成图表
   |-- 生成章节内容
   |
4. 组装完整文档
   |
5. 执行质量检查
```

### 5.2 阶段六：组装完整文档

**目的**: 组装完整文档

**依赖前序阶段**:
- 已生成目录结构
- 已完成全部章节内容
- 已准备文档元数据

**阶段产物**: 完整的 DeepWiki 文档（Markdown 格式）

---

### 5.3 阶段七：执行质量检查

**目的**: 检查文档质量

**检查对象**:
- 完整文档
- 章节结构
- 源文件引用
- 图表、表格与语言规范符合性

**检查项说明**：
| 检查项 | 说明 |
|--------|------|
| has_overview | 包含"系统概述"章节 |
| has_architecture | 包含"系统架构"章节 |
| has_source_files | 每页有"相关源文件"列表 |
| has_diagrams | 核心架构有 Mermaid 图表 |
| has_tables | 配置参数有表格说明 |
| is_chinese | 文档使用简体中文 |
| no_emoji | 不包含 emoji 表情 |

## 6. 使用示例

### 6.1 为新项目生成文档

```text
1. 读取项目根目录、README 和关键源码区域，判断项目类型与文档组织模式。
2. 基于项目类型生成目录结构，并补充领域特定章节。
3. 遍历每个章节，提取相关源文件。
4. 当章节内容复杂到仅靠文字难以表达时，补充 Mermaid 图表。
5. 根据源文件、图表和章节边界生成正文内容。
6. 汇总全部章节并组装成完整文档。
7. 对照质量检查项确认结构、引用、图表和语言规范均已闭环。
```

## 8. Skill 扩展指南

### 8.1 添加新流程阶段

新增流程定义应遵循以下模板：

````markdown

**目的**: [简要说明]

- 信息 1
- 信息 2

**阶段产物**:
- 产物 1
- 产物 2

**处理逻辑**:
1. 步骤 1
2. 步骤 2
````

### 8.2 Skill 组合模式

Skills 可以组合使用，形成更复杂的工作流：

| 组合模式 | 说明 | 适用场景 |
|----------|------|----------|
| 串行 | A -> B -> C | 依赖前序结果 |
| 并行 | A, B, C -> D | 独立任务聚合 |
| 条件 | A -> (B or C) | 根据条件分支 |
| 循环 | A -> B -> A | 迭代优化 |

### 8.3 错误处理

每个 Skill 应处理以下错误情况：

| 错误类型 | 处理方式 |
|----------|----------|
| 输入无效 | 返回错误信息，不执行 |
| 文件不存在 | 跳过，记录警告 |
| 解析失败 | 使用默认值，记录警告 |
| 超时 | 返回部分结果，标记未完成 |

## 9. 最佳实践

### 9.1 文档生成建议

1. **先分析后生成**：确保项目类型判断准确
2. **迭代优化**：生成后进行质量检查，迭代改进
3. **人工审核**：AI 生成的文档应经过人工审核
4. **版本关联**：文档应与代码版本关联

### 9.2 常见问题

| 问题 | 解决方案 |
|------|----------|
| 章节内容空泛 | 增加源码分析深度 |
| 图表过于复杂 | 拆分为多个简单图表 |
| 文件关联不准确 | 优化文件匹配算法 |
| 缺少关键章节 | 检查项目类型判断 |

### 9.3 性能优化

1. **缓存分析结果**：避免重复分析
2. **并行处理章节**：独立章节可并行生成
3. **增量更新**：只更新变化的章节
4. **懒加载图表**：按需生成复杂图表
