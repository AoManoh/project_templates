# 重构治理 Skill 规范

## 1. 目标

本规范用于约束重构任务的基线采集、阶段设计、阶段退出和兼容层清理。

为什么：重构最大的风险不是改错一行代码，而是让半完成状态、旧事实源和兼容层跨阶段扩散。

---

## 2. 基线证据清单

开始设计阶段计划前，至少要回答以下问题：

1. 当前真实行为由哪些代码路径实现。
2. 哪些调用方依赖旧实现。
3. 哪些测试、脚本、配置和文档描述了当前状态。
4. 哪些兼容层、双轨入口或迁移代码已经存在。
5. 当前是否存在已知但未清理的历史遗留项。

---

## 3. 阶段文档模板

`docs/refactor/YYYY-MM-DD-{scope}.md` 至少包含：

1. **重构目标**：为什么要重构，而不是继续堆补丁。
2. **当前基线**：旧实现、依赖方、测试和文档事实。
3. **阶段矩阵**：每阶段的目标、范围、进入门禁、退出门禁。
4. **不得跨阶段遗留项**：本阶段必须清掉的内容。
5. **兼容层策略**：是否允许暂存、由谁负责、最晚何时删除。
6. **验证方案**：每阶段的测试与检查清单。
7. **最终收敛标准**：何时才算真正完成重构。

---

## 4. 退出门禁

任一阶段退出前，必须同时满足：

| 类别 | 退出要求 |
|------|----------|
| 代码 | 当前阶段范围内的新旧边界已经清晰且一致 |
| 文档 | 受影响的说明、注释、脚本与阶段文档已同步 |
| 验证 | 已执行阶段定义的最小充分验证 |
| 清理 | 本阶段承诺清理的旧逻辑、兼容层、过期事实源已清掉 |
| Review | 已完成人工 review；可用时补充 Codex 审查 |
| 完成验证 | 满足 AGENTS.md §5 完成验证底线 |

---

## 5. 兼容层约束

兼容层只在以下条件同时满足时允许暂存：

1. 删除兼容层会阻断当前阶段目标。
2. 用户明确批准保留。
3. 文档中写明保留范围、风险、验证方式和最晚删除阶段。

以下情况禁止保留兼容层：

- 只是为了少改调用方而偷懒。
- 没有明确 owner。
- 没有最晚删除时间点。

---

## 6. 四类不得跨阶段遗留的债务

1. **技术债**：失效入口、无主兼容层、双轨分支。
2. **文档债**：旧文档仍宣称旧实现是当前真相。
3. **验证债**：阶段切换完成但没有实际验证记录。
4. **半完成状态债**：上一阶段的清理责任被推到下一阶段但未显式声明。
