# 重构治理 Skill

**skill_id**: `refactor-governance`
**版本**: 1.0.0
**output_dir**: `docs/refactor/`

---

## 1. 概述

本技能定义 AI Agent 执行阶段性重构任务时的治理流程，适用于替换实现、抽象收敛、迁移边界调整、兼容层治理和旧事实源清理。

目标不是尽快“把新代码接上”，而是确保每个阶段都拥有清晰的进入门禁、退出门禁、债务清理责任和单一事实源。

### 1.1 触发条件

| 触发方式 | 条件 |
|----------|------|
| 显式触发 | 用户指令包含关键词：`重构`、`迁移`、`替换实现`、`抽象收敛`、`兼容层清理`、`refactor` |
| 场景触发 | 任务核心是替换旧实现、阶段迁移、删旧留新、收敛双轨或定义阶段计划 |

### 1.2 前置依赖

| 依赖 | 用途 | 必要性 |
|------|------|--------|
| Augment Codebase | 定位旧实现、调用链和影响面 | 必需 |
| view 工具 | 读取真实文件确认 | 必需 |
| code-review Skill | 验证阶段退出质量 | 推荐 |
| git-governance Skill | 高风险迁移前的基线与分支保护 | 推荐 |
| Codex CLI | 多模型交叉审查 | 推荐 |

## 2. 强制行为

| 行为 | 时机 |
|------|------|
| 读取 SPEC.md | 开始前 |
| 写入阶段文档前，必须先确认项目根为当前 `AGENTS.md` 所在目录；所有 `docs/refactor/*` 路径相对该目录解析 | 制定阶段计划前 |
| 在设计阶段前采集基线证据 | 制定阶段计划前 |
| Skill 触发后必须生成阶段文档 | 开始重构前 |
| 每个阶段都要写清进入门禁、退出门禁和不得跨阶段遗留项 | 设计阶段时 |
| 未经用户批准，不得让兼容层、双轨实现或旧事实源跨阶段遗留 | 阶段退出前 |
| 完成一个阶段后必须先 review 与自检，再进入下一阶段 | 阶段完成后 |
| 如安装了 Codex CLI，应在关键阶段退出前调用 Codex 辅助审查 | review 阶段 |

## 3. 快速参考

### 3.1 阶段类型

| 阶段 | 目标 | 典型产物 |
|------|------|----------|
| 基线阶段 | 搞清当前真实行为、依赖和风险 | 基线证据、调用链、风险列表 |
| 切换阶段 | 引入新实现并切换调用入口 | 新旧边界、验证结果、回退策略 |
| 清理阶段 | 删除旧实现、兼容层、过期文档与脚本 | 清理记录、最终事实源 |

### 3.2 高风险信号

| 信号 | 为什么危险 |
|------|-------------|
| 双轨实现长期并存 | 维护成本和认知成本会指数上升 |
| 新旧事实源同时存在 | 后续任务会基于不同基线继续演化 |
| 迁移只写“后续清理” | 等价于把最难的部分延期且失去约束 |
| 阶段边界只写目标不写退出标准 | 无法判断何时可以安全进入下一阶段 |

### 3.3 产物命名

```
docs/refactor/YYYY-MM-DD-{scope}.md
```

文档中必须包含阶段矩阵和“不得跨阶段遗留项”清单。

## 4. Skill 定义

### 4.1 capture_baseline

**目的**: 在开始改造前搞清楚“现在到底是什么”，避免对旧系统做想象式重构。

**执行步骤**:
1. 通过源码、测试、文档和运行脚本确认当前真实行为。
2. 列出调用入口、依赖方、配置项和相关文档。
3. 在阶段文档中记录当前风险与不可跳过的验证项。

### 4.2 design_stages_and_gates

**目的**: 把重构拆成可审计的阶段，而不是一串模糊的“先改这里再看看”。

**执行步骤**:
1. 按阶段定义目标、改动范围、进入门禁和退出门禁。
2. 写清每阶段必须清掉的技术债、文档债、验证债和半完成状态债。
3. 明确哪些内容绝对不能跨阶段遗留。

### 4.3 execute_one_stage_only

**目的**: 保持阶段边界干净，避免上一阶段的未完事项污染下一阶段。

**执行步骤**:
1. 只执行当前阶段已定义的内容。
2. 当前阶段未闭环前，不进入下一阶段。
3. 如发现阶段边界失真，立即停止推进并回到阶段文档修正。

### 4.4 remove_old_truth_and_compatibility

**目的**: 防止“新实现接上了，但旧实现/旧文档/兼容层还留着”成为默认结局。

**执行步骤**:
1. 当新事实源生效时，删除或改写旧事实源。
2. 清理兼容层、双轨入口、迁移脚本和过期文档。
3. 若必须暂时保留，记录用户批准、保留范围和最晚删除阶段。

### 4.5 validate_stage_exit

**目的**: 确保阶段退出基于证据，而不是基于主观感觉。

**执行步骤**:
1. 执行阶段定义的测试、检查和人工验证。
2. 对照退出门禁确认没有未声明遗留项。
3. 完成 review 后，才能把阶段状态标记为完成。
