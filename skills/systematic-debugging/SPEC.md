# 系统化调试 Skill 规范

**版本**: 1.1.0
**适用范围**: 中大型调试任务的根因定位、修复验证与调试记录

---

## 1. 目标

本规范用于约束调试任务的排查流程、证据采集和修复验证标准。

为什么：调试最常见的失败不是"修不了"，而是在未定位根因的情况下反复尝试，最终修复了症状但留下了隐患。

---

## 2. 调试流程约束

调试必须按以下阶段推进，禁止跳跃：

| 阶段 | 目标 | 退出条件 |
|------|------|----------|
| 复现 | 确认故障可稳定触发 | 有明确的复现步骤和故障证据 |
| 定位 | 缩小到具体代码路径 | 根因假说有源码级证据支撑 |
| 修复 | 最小修改消除根因 | 修改仅涉及根因相关代码 |
| 验证 | 确认修复有效且无回归 | 原始复现步骤不再触发故障，相关测试通过 |

---

## 3. 调试记录模板

`docs/debug/YYYY-MM-DD-{scope}.md` 至少包含：

1. **故障现象**：用户报告或系统表现的异常行为。
2. **复现步骤**：触发故障的最小操作序列。
3. **故障证据**：错误信息、日志片段、堆栈追踪。
4. **排查过程**：逐步缩小范围的推理链。
5. **根因定位**：源码级的问题定位（文件路径:行号）。
6. **修复方案**：具体改了什么，为什么这样改。
7. **验证结果**：修复后的验证命令和实际输出。

---

## 4. 退出门禁

调试 task 退出前，必须满足以下条件：

| 类别 | 退出要求 |
|------|----------|
| 根因 | 已定位到源码级根因，不是猜测 |
| 修复 | 修改范围仅覆盖根因相关代码，无附带"顺便改" |
| 验证 | 原始复现路径验证通过，相关测试无回归 |
| 文档 | 中大型调试已生成调试记录 |
| 清理 | 调试过程中的临时代码、日志语句已清除 |
| 完成验证 | 满足 AGENTS.md 完成前证据门禁（`GATE-EVIDENCE`） |

---

## 5. 根因假说标准

根因假说必须满足以下要求：

| 要求 | 说明 |
|------|------|
| 可定位 | 指向具体的源码位置（文件:行号） |
| 可解释 | 能说明为什么这段代码会产生观察到的故障 |
| 可验证 | 能通过修改这段代码来消除故障 |
| 可反驳 | 如果修改后故障未消除，假说应被推翻而不是追加更多修改 |

---

## 6. 禁止清单

1. 在未复现故障的情况下直接修改代码。
2. 同时修改多处"试试看哪个能修好"。
3. 修复后不执行原始复现步骤就宣称完成。
4. 把调试临时加入的 `console.log`/`print` 留在最终提交中。
5. 只消除错误信息但不验证功能行为是否恢复正常。
