# 系统化调试 Skill

**skill_id**: `systematic-debugging`
**版本**: 1.0.0
**output_dir**: `docs/debug/`

---

## 1. 概述

本技能定义 AI Agent 在调试阶段的治理流程，确保 bug 修复遵循"先定位根因，再修复"的原则，而不是基于猜测反复尝试。

目标不是让调试变慢，而是让调试过程可追溯、根因可定位、修复可验证。

### 1.1 触发条件

| 触发方式 | 条件 |
|----------|------|
| 显式触发 | 用户指令包含关键词：`调试`、`debug`、`排查`、`定位问题`、`根因分析`、`bug` |
| 场景触发 | 测试失败、运行时异常、行为偏离预期、性能异常、间歇性故障 |

### 1.2 前置依赖

| 依赖 | 用途 | 必要性 |
|------|------|--------|
| AGENTS.md | 全局约束承接（源码至上、语义检索优先、完成验证底线） | 必需 |
| auggie-mcp Skill | 源码语义检索、事实检索、影响面定位 | 必需 |
| 源码访问 | 根因定位 | 必需 |
| view 工具 | 读取真实文件确认 | 必需 |
| 测试框架 | 验证修复 | 推荐 |
| 日志/错误输出 | 故障证据 | 推荐 |

### 1.3 关联规范

详细约束见：[SPEC.md](./SPEC.md)

## 2. 强制行为

| 行为 | 时机 |
|------|------|
| 读取 SPEC.md | 开始前 |
| 写入调试记录前，必须先确认项目根为当前 `AGENTS.md` 所在目录；所有 `docs/debug/*` 路径相对该目录解析 | 记录调试过程前 |
| 先复现，再定位，再修复 | 调试全程 |
| 修复前必须形成根因假说 | 修改代码前 |
| 修复后必须验证且记录结果 | 修改代码后 |
| 不得在未定位根因时进行投机性修复 | 调试全程 |
| 复杂调试必须生成调试记录 | 调试完成后 |

## 3. 快速参考

### 3.1 适用边界

| 调试规模 | 判定信号 | 处理要求 |
|----------|----------|----------|
| 小 | 错误信息明确、根因显而易见、单文件修复 | 不强制触发本 Skill，按常规流程修复 |
| 中 | 根因不明确、涉及多文件交互、需要多步排查 | 触发本 Skill，生成简要调试记录 |
| 大 | 间歇性故障、跨模块问题、涉及环境/配置/并发 | 触发本 Skill，生成完整调试记录 |

### 3.2 产物命名

```
docs/debug/YYYY-MM-DD-{scope}.md
```

`scope` 使用 kebab-case，推荐采用故障现象或模块名。

### 3.3 禁止事项速查

| 禁止事项 | 为什么 |
|----------|--------|
| 未复现就猜测根因 | 猜测会导致修复了错误的问题 |
| 同时修改多处来"试试看" | 无法确定哪个修改真正解决了问题 |
| 修复后不验证就宣称完成 | 无验证的修复可能引入新问题 |
| 只修症状不查根因 | 症状消失不等于问题解决 |
| 调试过程不记录就结束 | 同类问题再次出现时无法快速定位 |

## 4. Skill 定义

### 4.1 reproduce_and_isolate

**目的**: 确认故障可复现，并缩小问题范围。

**执行步骤**:
1. 确认故障的触发条件和复现步骤。
2. 采集故障现场证据：错误信息、日志、堆栈、状态快照。
3. 缩小范围：排除无关模块、定位到最小复现路径。

### 4.2 form_root_cause_hypothesis

**目的**: 基于证据形成根因假说，而不是基于直觉猜测。

**执行步骤**:
1. 阅读相关源码，理解当前实现逻辑。
2. 对比预期行为与实际行为的差异点。
3. 形成根因假说并写明支撑证据。

**关键约束**:
- 假说必须能被验证或反驳，不能是模糊的"可能是这里的问题"。

### 4.3 verify_fix

**目的**: 确保修复真正解决了根因，且不引入回归。

**执行步骤**:
1. 实施最小修复（只改根因相关代码）。
2. 用原始复现步骤验证故障已消除。
3. 执行相关测试确认无回归。

### 4.4 document_debug_session

**目的**: 让调试过程可追溯，同类问题可复用。

**执行步骤**:
1. 按 SPEC.md 模板生成调试记录。
2. 写入 `docs/debug/YYYY-MM-DD-{scope}.md`。
3. 记录根因、修复方案和验证结果。

## 5. Skill 编排流程

### 5.1 标准调试流程

```
1. reproduce_and_isolate
   |
2. form_root_cause_hypothesis
   |
3. verify_fix
   |
4. document_debug_session
```

### 5.2 快速修复流程（小规模）

```
1. 确认错误信息和根因
   |
2. 修复并验证
```
